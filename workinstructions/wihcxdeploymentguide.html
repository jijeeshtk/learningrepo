Installation Steps

StepsScreenshots
1. Login to VMC Cloud and select VMC on AWS service » SDDC
Select on the Integrated Services and click on Open HCX
2. Go to VMware HCX console and under SDDCs tab click on Deploy HCX
3. Also, in the meantime create the Activation Keys
4. Once HCX manager deployment is completed, go back to VMware Cloud Console and select Settings tab
In the HCX Information section, click on the HCX FQDN
5. Login with cloudadmin credentials (Default vCenter Credentials) to VMware HCX
6. Click on System Updates in the left panel and wait for the REQUEST DOWNLOAD LINK button to appear and click on it
7. Click on the VMWARE HCX to download VMware HCX Connector
8. In On-prem vCenter under management cluster deploy VM from VMware HCX Connector OVF Template (downloaded in step 6)
9. Fill in all the details required to deploy the HCX Connector like
name, folder to place VM, compute resource, accept license agreements, storage, networks and in customize template admin and root user passwords, hostname, IP address, prefix length, default gateway, DNS server, NTP Server etc.

Note: Make sure the HCX connector entry is present in DNS Server
10. In a browser tab go to: https://fqdn-or-ip-hcx:9443 and login with user admin credentials (created in step 8)
11. Enter HCX License Key is obtained from the VMC portal and HCX Activation Server then click on Activate
Also, enter the Location of your datacenter
System Name for HCX Appliance
vCenter information (Ensure user with admin rights is entered)
SSO/PSC Information
Click Restart button
12. Go to Configuration tab and click vSphere Role Mapping, click Edit, and enter the group(s) as necessary to have access to vCenter User Groups for HCX.
13. From the HCX UI, click on Site Pairing and click Connect to Remote Site button
Provide HCX cloud URL, username, password and click Connect

Compute Profile

StepsScreenshots
1. At the source site, open vSphere Client and navigate to the HCX plug-in » Interconnect » Multi-Site Service Mesh » Compute Profiles. Click on Create Compute Profile.
Follow the instructions given below
2. A Compute Profile contains the compute, storage, and network settings that HCX uses on this site to deploy the Interconnect-dedicated virtual appliances when a Service Mesh is added.
First , Give your Compute Profile a name
3. Choose the HCX services you want to activate.
4. i) Select Resources from the drop-down menu. Choose each cluster that should have HCX services active.
Click Continue
ii) From the provided drop-down menu, choose the resource pool, datastore, and folder to be used for deploying HCX Interconnect appliances.
5. i) Choose the Network Profile that will allow you to access vCenter’s management interface and the ESXi hosts or click Create Network Profile to create it.
ii) Select an Uplink Network Profile by using the drop-down menu. Select one or more already-existing network profiles.
iii) Select the network profile that enables access to the vMotion interfaces on ESXi hosts.
iv) Choose a Network Profile that enables access to the ESXi Hosts vSphere Replication interface. This is generally the same as a Management Network Profile.
v) Select Network Containers Eligible for Network Extension. Networks within the selected virtual switches or transport zones become eligible for HCX Network Extension operations.
6. For the specified SDDC, review and approve these connections.
7. Review the configuration. The chosen configurations are displayed in the topology diagram. Click Finish to Create the Compute Profile.
8. At the destination site, navigate to https://hcx-cloud-ip-or-fqdn » Multi-Site Service Mesh » Compute Profiles and follow the similar steps mentioned above.

Service Mesh Creation

StepsScreenshots
1. In the vSphere Client, navigate to HCX » Interconnect » Multi-Site Service Mesh » Service Mesh tab. . Click on Create Service Mesh.
A Service Mesh is the effective HCX services configuration for a source and a destination site. You can add a Service Mesh to a connected Site Pair that has a valid Compute Profile created on both of the sites.
Follow the instructions given below
2. Choose the paired sites between which you wish to provide hybrid mobility, and choose one compute profile for both the source and the distant sites to enable hybridity services.
3. Choose the HCX services you want to activate.
4. The HCX connection by default uses Uplink Network Profiles set up in the Compute Profile for the source and destination sites. One can alter the default configuration. Choose the source uplink’s network profile. If necessary, use advanced Configuration.
5. Give your Service Mesh a name
6. Review the configuration. The chosen configurations will be displayed below. Click Finish to Create the Service Mesh.

Network Extension

HCX Network Extension (HCX-NE), you can extend the virtual machine (VM) networks to an HCX remote site. Virtual machines that are migrated or created on the extended segment at the remote site behave as if on the same L2 segment as virtual machines in the source environment. With Network Extension, the default gateway for the extended network is only connected at the source site. Traffic from virtual machines in remote sites that must be routed to a different L3 network flow through the source site gateway.

Using Network Extension with VMware HCX Migration you can:

  • Retain the IP and the MAC addresses of the VM, and honor existing network policies.
  • Extend VLAN-tagged networks from a VMware vSphere Distributed Switch.
  • Extend NSX segments.

Requirements

  • Never extend the networks used to create the network profiles.
  • Never use HCX to extend the vSphere Management network or other VMkernel networks (for example: vMotion, vSAN, replication) to the remote site.
StepsScreenshots
1. At the source site, open vSphere Client and navigate to the HCX plug-in » Services » Network Extension. Click on Extend Network.
Follow the instructions given below.
2. Choose the Mesh service you wish to utilize. Select one or more NSX logical switches or Distributed Port Groups. You may use the filters at your advantage to hide networks that are not eligible for extension, networks without linked virtual machines, and networks without extension.
3. Select the Destination First Hop Router , this drop-down menu allows for the selection of a router. As an example, enter 172.22.70.1/24 as the Gateway IP address and Prefix Length for the network extension. Select the Extension appliance. Choose between an appliance and a Network Extension High Availability group.
Allow Overlapping VLAN: The HCX Manager stops you from expanding networks that share the same VLAN ID and gateway IP address. Bypass the system and enable multiple VLAN IDs by using this option.
4. Finally, click Submit.
Go to the HCX Dashboard and scroll down to the Activity Logs display to see the task status.
5. For a summary of data on the number of extended networks, extension appliances, mobility optimized networks, and network extension provided by a HA group, go back to the Network Extension page.

HCX Migration

Multiple migration techniques can be used to transfer virtual machines across data centers with HCX activation. The various migration steps are described in the following steps.

Reqirements

  • HCX Interconnect tunnels must be up/active.
  • HCX vMotion requires 100 Mbps or higher throughput capability.
  • Hybrid Interconnect, Bulk Migration, vMotion, and Replication Assisted vMotion services must be activated and in a healthy state in the relevant Service Mesh.

Vmotion-Migration

VMware HCX vMotion can transfer a live Virtual Machine from a  vCenter Server with HCX activation to a destination site with HCX activation (or viceversa). The virtual machine’s active memory, execution status, IP address, and MAC address are all recorded throughout the vMotion transfer. The connectivity, including the available bandwidth and the latency between the two locations, will determine how long the transfer will take.

Replication-assisted VMotion

HCX Replication Assisted vMotion (RAV) uses the HCX along with replication and vMotion technologies to provide large scale, parallel migrations with zero downtime.

Replication Assisted vMotion creates two folders at the destination site. Both the virtual machine disk information and the definition of the virtual machine architecture are included in separate folders. The functioning of the virtual machine at the destination location is unaffected by this typical RAV migrating behavior.

Bulk-Migration

Bulk migration uses the host-based replication to relocate a virtual machine between HCX data centers.

To reduce the downtime, the source VM remains online during the replication and is bootstrapped on the destination ESX host after replication completes.

Migration Steps

StepsScreenshots
1. At the source site, open vSphere Client and navigate to the HCX plug-in » Services » Migration. Click on Migrate.
Follow the instructions given below.
2. Please verify the on-premises to cloud remote connectivity. To migrate a virtual machine, select it and then click Add.
3. Transfer and Placement - Use the provided drop-down menu to choose the necessary information. For the Destination Computer Container, storage, Migration Profile, Destination folder, and Virtual Disk Format fields, we must provide valid values.
Switchover - Choose an option Remove Snapshots, Force unmount ISO Images, and Force power off VM.
Extended Options - Enable VM options according to your needs.
4. Click Validate . Prior to migration , Rectify the faults and warnings.
5. Click Go. Prior to migrating, it will first perform a basic sync with the destination.
6. Once the migration is complete, we can verify that it was successful and that the virtual machine will be visible at the destination site..
7. Reverse Migration is possible, we only need select one option.

Analysis of CI configuration modifications following VM migration to VMC

  • The virtual machine can be viewed in Service Now under the VMC VCenter after being migrated from on-prem to VMC.
  • Since discovery has been enabled, if we modify CPU, Disk, or Memory during migration, the modified values will be reflected in Service Now as well.
  • The VCenter Reference and Vcenter UUID will be changed since the VM has been moved to the VMC.
  • After migration, the VM UUID and BIOS UUID will both stay the same.
